# R08 에이전트 협업 명세

**검토용 초안**입니다. [PR #13 머지 커밋](https://github.com/organis-labs/organis/commit/513b98cb514fee0eebff5079902aaae0985afbad)을 기준으로 [M2.5 목표](../roadmap.md#m25--room-participants-and-bounded-collaboration), [로컬 실행 계약](../local-execution.md), [프로젝트 권한 계약](workspace-permissions.md)을 대조했습니다.

## 출발점과 첫 범위

[PR #12](https://github.com/organis-labs/organis/pull/12)는 Claude Code 연결 확인과 공식 로그인·읽기 전용 터미널 예제를 제공합니다. [PR #13](https://github.com/organis-labs/organis/pull/13)의 [데스크톱 변경 미리보기](codex-read-only.md#propose-and-apply-a-single-file-change-in-desktop)는 사용자가 등록한 프로젝트의 루트에서 기존 UTF-8 텍스트 파일 한 개를 고르는 흐름입니다. 원본과 교체할 내용은 각각 최대 4 KiB입니다. Codex가 읽기 전용으로 변경안을 만들고 사용자가 확인 창에서 승인하면 Organis가 적용을 시도합니다.

첫 협업에서는 이 파일 범위를 유지합니다. 로컬 방에서 Claude가 계획을 제안하고, Organis가 Codex에 배정하며, 사용자가 변경을 승인하고, Claude가 적용 결과를 검토합니다. Claude의 구조화 실행·종료 확인과 방 단위 협업은 R09 구현 범위입니다. 일반 명령 실행, 다중 파일 쓰기, 원격 호스트, 백그라운드 위임과 자동 승인은 이 흐름의 권한에 포함되지 않습니다.

## 역할과 요청 대상

| 역할 | 할 수 있는 일 |
| --- | --- |
| 사용자 | 참여자와 리드 선택, 프로젝트와 대상 파일 선택, 전달 자료 확인, 승인·거절, 취소, 재수정 요청 |
| Claude | 리드로서 계획과 배정안 작성, 적용된 결과 검토, 근거를 붙여 재수정 제안 |
| Codex | 받은 작업 요약과 선택 파일로 읽기 전용 변경안 작성 |
| Organis | 대상과 권한 확인, 배정·실행·산출물 연결, 승인 검증과 파일 적용, 종료·복구 관리 |

연결 설정과 방 참여는 별개입니다. 참여자를 추가해도 작업을 시작하거나 기존 대화를 보내지 않습니다. 대상을 생략하면 현재 리드에게 전달합니다. 메시지의 `@참여자`와 작성창의 수신자 선택은 방 안의 한 참여자를 가리켜야 합니다. 두 대상이 다르거나 대상이 없거나 역할이 맞지 않으면 입력을 보존하고 전송을 막습니다. 링크·인용·코드 블록의 문자열에는 라우팅 효력이 없습니다. 개인 메시지는 지정한 참여자에게만 전달합니다.

Organis는 방·참여자·역할·작업·시도·산출물 관계를 기록합니다. 참여자별 활성 실행은 한 건, 공유 작업공간의 동시 쓰기는 한 건입니다. 활성 작업에서 참여자를 빼려면 해당 작업을 취소하거나 종료까지 유지해야 합니다. 리드 변경은 이후 배정에 적용합니다.

## 공유 범위

| 수신자 | 처음 전달하는 내용 |
| --- | --- |
| 계획 담당 Claude | 이번에 선택한 사용자 요청, 목표와 제약, 사전에 확인한 파일 경로·설명과 사용자가 고른 자료 |
| 작업 담당 Codex | 계획에서 뽑은 작업 요약과 수용 기준, 허용 경로, 사용자가 선택한 기존 파일의 원본 내용 |
| 검토 담당 Claude | 같은 작업의 계획 요약, 실제 적용한 변경분, 검증 상태와 테스트 명령·종료 코드·결과 요약 |
| 재수정 담당 Codex | 재수정 제안 요약, 수용 기준, 선택 파일의 현재 원본 |

전송 전 화면에 수신자, 제공자, 메시지, 산출물과 파일 범위를 표시합니다. 방 전체 기록, 개인 메시지, 계정 정보, 자격증명, 환경 변수, 도구 원본 로그는 기본 전달 범위에서 제외합니다. 파일이나 산출물 내용은 실행 권한을 부여하지 않습니다. 참조는 보내기 직전에 접근 가능 여부와 버전을 다시 검사합니다. 내용이나 대상이 바뀌었으면 사용자에게 다시 보여줍니다. 제공자에 이미 전달된 내용은 로컬 취소로 회수할 수 없습니다. 로컬 보존·삭제 정책은 구현 전에 확인합니다.

## 실행과 승인

1. 사용자가 협업 요청을 보내면 Organis가 역할·연결·파일 범위를 검사하고 Claude 계획 실행을 시작합니다. 사용자에게 계획 산출물과 Codex에 전달할 작업 요약을 보여줍니다.
2. 사용자가 배정을 확인하면 Organis가 표시한 자료만 Codex에 보냅니다. Codex 작업이 끝나면 원본 대비 변경 내용, 대상 파일, 적용 범위를 보여주고 사용자 승인 대기로 전환합니다. 배정 확인은 파일 변경 권한을 부여하지 않습니다.
3. **적용 승인**은 현재 작업·시도·프로젝트·대상 파일과 원본·변경안 버전에 묶인 결정입니다. Organis는 경로와 파일 동일성, 승인 범위, 작업공간 점유를 다시 확인하고 승인에 연결된 변경을 한 번만 적용합니다. 승인 기록과 적용 결과를 별도로 표시합니다. 파일·내용·시도 변경, 거절·취소·만료 후에는 새 변경안과 새 승인이 필요합니다.
4. 파일 적용을 확인하면 Organis가 그때 기록한 변경분을 Claude에 보냅니다. 검토는 `검토 통과`, `재수정 제안`, `검토 실패`로 남깁니다. 테스트한 경우에는 실행 명령, 주체, 종료 코드, 결과와 대상 버전을 기록합니다. 실행 증거가 없으면 **테스트 미실행**으로 표시합니다. Claude 검토 결과만으로 테스트 통과를 표시하지 않습니다.

## 취소·복구·재수정

| 시점 | Organis 동작과 화면 |
| --- | --- |
| 배정 전·승인 대기 | 대기 중 입력·승인을 무효화합니다. 적용 전에는 파일을 그대로 둡니다. |
| 계획·변경안·검토를 실행 중 | 취소를 기록하고 실행을 중단합니다. 프로세스 종료를 확인할 때까지 **취소 중**을 표시하고 점유를 유지합니다. 종료를 확인할 수 없으면 **종료 확인 필요**를 표시합니다. |
| 적용이 끝난 뒤 | 후속 검토와 대기 작업을 멈출 수 있습니다. 이미 적용한 변경과 적용 기록은 남습니다. 원복은 현재 파일을 기준으로 사용자가 다시 승인할 별도 변경입니다. |
| 적용 중 또는 재시작 뒤 결과가 불확실함 | 적용·미적용을 확인하기 전에는 결과를 **확인 필요**로 남깁니다. 동일 명령을 자동 재전송하지 않습니다. 사용자가 현재 파일을 확인한 뒤 새 시도를 선택합니다. |
| Claude가 재수정을 제안함 | 사용자가 제안과 남은 횟수, Codex에 보낼 내용을 확인합니다. 같은 파일의 최신 내용으로 새 시도를 시작하고 새 변경안을 다시 승인받습니다. 한도를 소진하면 진행을 멈추고 선택지를 표시합니다. |

중복 요청에는 동일한 작업·시도 상태를 반환합니다. 승인과 취소가 겹치면 Organis가 파일 적용 직전에 승인 소비·취소의 순서를 한 곳에서 결정합니다. 취소가 먼저면 파일은 그대로 남고, 쓰기가 끝났으면 적용 완료 기록을 보존합니다. 작업 중 연결이 끊기면 마지막으로 확인한 실행 상태를 표시하고 같은 변경을 다시 적용하지 않습니다. 미전송 큐는 취소한 작업에 이어서 실행하지 않습니다. 소유권이 불명확하면 새 실행으로 이어가기 전에 실행 종료와 작업공간 상태를 확인합니다.

## 채팅 작성창 계약

- Markdown 원문을 작성하고 미리 봅니다. 원문을 보존하고 미리보기에서 원시 HTML, 스크립트와 자동 외부 리소스 로드를 차단합니다. 사용자의 조합 입력을 전송 단축키로 처리하지 않습니다.
- 수신자, 실행 방식, 모델, 권한을 따로 표시합니다. 실행 방식의 선택지는 `Codex`, `Claude`, `LLM`이며 모델 메뉴를 바로 옆에 둡니다. 각 어댑터가 보고한 모델과 기능만 활성화합니다. 지원하지 않는 선택에는 이유를 붙입니다. 설정에서 요청한 권한과 실행 시 실제 적용되는 권한을 함께 표시합니다. 작성창에서 권한과 모델을 바꾸면 다음 요청에 적용합니다. 현재 실행에 부여한 권한을 철회하면 해당 실행을 취소합니다.
- **지금 전달**은 실행·응답 중인 참여자에게 추가 지시를 보내고 수신 확인을 표시합니다. 전송 전 공유 범위를 보여줍니다. 수신자가 현재 실행과 다르거나, 승인 대기 중이거나, 어댑터가 지원하지 않으면 초안을 보존합니다.
- **대기열에 추가**는 확인한 수신자·제공자·모델·권한·자료 버전과 메시지를 보관합니다. 두 전송 방식을 자동으로 바꾸지 않습니다. 전송 전 삭제할 수 있고, 앞선 실행이 정상 종료한 후에도 조건을 다시 검사합니다. 실패·취소·종료 미확인 또는 수신자·권한·자료 변경 시 보류하고 다시 확인받습니다. 등록 당시보다 넓어진 권한을 자동 적용하지 않습니다.

## R09 수용 기준

- 연결된 로컬 환경에서 사용자 요청 → Claude 계획 → 사용자 확인과 Codex 배정 → 변경안 → 사용자 승인과 한 파일 적용 → Claude 검토를 실행 ID와 산출물로 추적합니다.
- 취소·거절·만료·대상 변경·중복 요청 시 쓴 파일이 없거나 기존 성공 기록 한 건만 남습니다. 종료 미확인, 소유자 종료와 재시작, 적용 결과 미확인에서는 상태와 점유를 확인하고 자동 재적용을 막습니다.
- 없는 대상, 중복 멘션, 역할 불일치와 범위 밖 파일을 막습니다. 다른 참여자의 개인 메시지와 전체 방 기록이 계획·작업·검토 요청에 섞이지 않는지 합성 데이터로 확인합니다.
- Markdown 작성, 지원하지 않는 모델·권한 선택, 처리 중 즉시 전달과 큐, 미확인 전송·삭제·재수정 한도 도달을 같은 상태 계약으로 검증합니다.
